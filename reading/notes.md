# 22篇VLA论文：具体做法、结果与对比

更新：2026-10-22。原14篇保留固定PDF版本和图表页码。新增8篇目前只核对摘要，还没逐项检查全文与代码。页码从PDF阅读器第1页起算。

## 一、先弄清每组论文在做什么

| 分组 | 论文 | 主要问题 |
| --- | --- | --- |
| A · 多任务机器人模型 | RT-2、OpenVLA、π₀、Octo、π₀.₅、SmolVLA | 怎样让一个模型做不同任务？ |
| B · 共享训练数据 | Open X-Embodiment / RT-X | 不同机器人的示范能不能一起用？ |
| C · 算动作与继续训练 | ACT、Diffusion Policy、FAST、OpenVLA-OFT、LoRA | 怎样算动作，怎样减少训练花费？ |
| D · 测试任务与成功率 | LIBERO、LIBERO-Plus | 怎样测试机器人有没有做成？ |
| E · 训练时重点看什么 | Long-VLA、EGR、FrameSkip、PHASER | 哪些输入、时刻和旧示范更值得练？ |
| F · 输入出问题以后 | STRONG-VLA、MAIL-Bench / MINT、View Collapse、CARE | 画面变差或相机中断后会怎样？ |

先读RT-2 → OpenVLA → π₀，理解三种代表做法。再看OFT、动作相关方法和测试论文。最后两组介绍训练时挑哪些信息，以及输入出问题时的表现。分组只方便查阅，不表示同组方法完全一样。

几个词先说清楚：

| 论文常用词 | 这里指什么 |
| --- | --- |
| 策略 | 根据当前画面和要求，算下一步动作的模型。 |
| token | 模型读写的小单位；动作token通常是代表动作的编号。 |
| 微调 | 在已经学过的模型上，用新示范继续训练。 |
| 动作块 | 一次预测后面几步的动作。 |
| 泛化 | 没有专门练过的物体、场景或要求，能不能应付。 |
| 鲁棒性 | 画面变差、输入被干扰后，还能不能做好。 |

## 二、22篇论文分别做了什么

| 论文 | 主要做什么 | 用什么资料 | 怎样给出动作或分数 | 和谁一起看 |
| --- | --- | --- | --- | --- |
| [01 RT-2](#paper-01) | 多任务机器人模型 | 网络图片文字和机器人示范 | 动作编号逐个输出，再换回控制数值 | 和OpenVLA一起看：都把动作写成编号。 |
| [02 OpenVLA](#paper-02) | 多任务机器人模型 | OXE等真实机器人示范 | 动作编号逐个输出，再换回控制数值 | OFT在它的基础上改变动作计算方式。 |
| [03 π₀](#paper-03) | 多任务机器人模型 | 多种机器人的自采与公开示范 | 反复修改一段动作数字，一起输出多步 | 和Diffusion Policy对照：都从随机数字逐步算动作，训练办法不同。 |
| [04 Open X-Embodiment / RT-X](#paper-04) | 共享示范数据 | 不同机构和机器人的操作记录 | 提供数据；RT-X用动作编号控制 | 为OpenVLA和Octo等提供操作示范。 |
| [05 Octo](#paper-05) | 多任务机器人模型 | 从OXE筛选的示范 | 多次修改随机数字，得到一段动作 | 和OpenVLA比整个模型，和Diffusion Policy比算动作的部分。 |
| [06 FAST](#paper-06) | 把动作记录写短 | 动作记录用于压缩工具；模型还需示范 | 短编号串，执行前还原成动作 | π₀.₅的训练中也用它；和逐时刻编号的办法对照。 |
| [07 π₀.₅](#paper-07) | 多任务机器人模型 | 机器人示范、网页图片文字、步骤标注 | 先选当前步骤，再计算动作 | 接着π₀发展，同时使用FAST。 |
| [08 SmolVLA](#paper-08) | 多任务机器人模型 | 主要是SO100社区示范，再加目标任务数据 | 一次多算几步，可边做边算 | 和π₀一起看动作计算；另外关注小模型与减少等待。 |
| [09 OpenVLA-OFT](#paper-09) | 算动作与继续训练 | 已有OpenVLA和目标任务示范 | 一次直接预测未来8步数值 | 直接接着OpenVLA训练；与π₀、Diffusion Policy的多次修改比较。 |
| [10 LIBERO](#paper-10) | 测试任务 | 仿真任务、示范、起始状态 | 任务完成与学新忘旧等分数 | 提供任务，供OFT等方法测试。 |
| [11 LIBERO-Plus](#paper-11) | 测试任务 | 改过测试条件的LIBERO任务 | 条件改变后的任务成功次数 | 在LIBERO基础上改变条件，检查高成功率是否可靠。 |
| [12 ACT](#paper-12) | 从示范学动作 | 人遥控机器人做任务的示范 | 多步预测，并平均同一时刻的结果 | 帮助理解为什么一次多算几步、怎样让动作更连贯。 |
| [13 Diffusion Policy](#paper-13) | 从示范学动作 | 目标任务的机器人示范 | 多次修改数字，先做几步再看 | Octo也用扩散办法；可与π₀和OFT对照。 |
| [14 LoRA](#paper-14) | 减少训练参数 | 已有模型和新数据；原论文主要测语言任务 | 只改变训练哪些参数，不规定动作 | 可用于OpenVLA等模型继续训练，和动作计算方式是两件事。 |
| [15 Long-VLA](#paper-15) | 训练时挑信息 | 操作示范与传感器记录；范围见原文 | 按阶段选择输入，再输出动作 | 按操作阶段挑输入，与EGR按传感器用途改变训练要求不同。 |
| [16 EGR](#paper-16) | 训练时挑信息 | 操作示范与传感器记录；范围见原文 | 按传感器是否有用改变训练要求 | 看哪个传感器此时有用，不按相同的移动阶段来分。 |
| [17 FrameSkip](#paper-17) | 训练时挑信息 | 操作示范与传感器记录；范围见原文 | 挑选训练用的画面与动作记录 | 挑当前训练用哪些记录；PHASER挑旧记录怎样再练。 |
| [18 PHASER](#paper-18) | 训练时挑信息 | 操作示范与传感器记录；范围见原文 | 安排旧任务的哪些步骤再练 | 解决学新忘旧，与单次训练时选帧不同。 |
| [19 STRONG-VLA](#paper-19) | 输入出问题以后 | 操作示范与传感器记录；范围见原文 | 先练受干扰数据，再练正常数据 | 改训练过程；CARE主要改执行多少步。 |
| [20 MAIL-Bench / MINT](#paper-20) | 输入出问题以后 | 操作示范与传感器记录；范围见原文 | 测试相机中断，并尝试补画面 | 相机持续中断，与CARE研究的一次短暂坏图不同。 |
| [21 View Collapse](#paper-21) | 输入出问题以后 | 操作示范与传感器记录；范围见原文 | 检查模型到底使用哪台相机 | 说明成绩提高可能来自改看另一台相机。 |
| [22 CARE](#paper-22) | 输入出问题以后 | 操作示范与传感器记录；范围见原文 | 前后预测作比较，决定先做几步 | 改变何时重新看画面，不改变训练示范。 |

## 三、把几条联系记住

1. **RT-2和OpenVLA：** 都把动作数值换成编号，一个接一个地预测。二者做法有关，不表示OpenVLA用了RT-2的模型参数。
2. **OpenVLA和OFT：** OFT接着OpenVLA训练，把动作编号改成直接计算后面多步的动作数值。
3. **Diffusion Policy、Octo和π₀：** 都能从随机数字开始逐步算出动作，但训练时学的修改办法不同。正文分别解释扩散和flow matching。
4. **ACT、FAST和SmolVLA：** ACT一次多算几步；FAST让动作记录更短；SmolVLA减少模型计算和等待。它们节省的东西不同。
5. **OXE、LIBERO和LIBERO-Plus：** OXE提供共享示范；LIBERO提供测试任务；LIBERO-Plus改变测试条件，检查成绩会不会掉。
6. **Long-VLA、EGR、FrameSkip和PHASER：** 分别挑输入、按传感器用途改变训练要求、挑训练时刻、安排旧示范重新练。
7. **STRONG-VLA、MINT、View Collapse和CARE：** 分别改训练过程、处理缺失画面、检查相机依赖，以及决定先执行几步。

### 01 RT-2

所用版本：2307.15818v1，26页。[原论文PDF](https://arxiv.org/pdf/2307.15818v1) · [原文来源](https://arxiv.org/abs/2307.15818v1)

- **问题：** 机器人没练过某些物体和说法时，能否用以前读图文学到的知识完成任务？
- **输入 → 输出：** 摄像头画面和一句要求 → 动作编号 → 还原成移动、转动、夹爪和停止命令。
- **核心改动：** 把每个动作数值分成256档，每档用一个编号表示。训练时既练机器人动作，也继续练看图回答问题。
- **证据：** Figure 4（p.8）和Table 4（p.23）：在对应测试里，RT-1面对未见情况平均32%，RT-2-PaLI-X为62%，已见任务成绩接近。Figure 6b（p.10）分别检查模型大小和训练办法的影响。
- **边界：** §5（p.11）和Figure 9（p.23）：能理解新说法，不等于学会新的手上技能。陌生物体的重量、摩擦等仍可能让它失败；计算也比较慢。

### 02 OpenVLA

所用版本：2406.09246v3，37页。[原论文PDF](https://arxiv.org/pdf/2406.09246v3) · [原文来源](https://arxiv.org/abs/2406.09246v3)

- **问题：** 能否公开一个机器人模型，让别人用自己的数据继续训练？
- **输入 → 输出：** 原版看一张图和一句指令 → 一个接一个输出动作编号 → 还原动作数值。
- **核心改动：** DINOv2和SigLIP两套网络处理图片，再把结果和指令交给语言模型。作者公开权重、代码，并测试怎样只更新少量参数。
- **证据：** Figure 5（p.9）看换机器人后继续训练的成绩；Table 1（p.10）中LoRA接近更新全部参数。注意该表用的是较小数据组合、只有SigLIP图像网络的版本；主模型见Figure 2（p.4）。
- **边界：** §6（p.11）：原版主要看一张图，编号要逐个算，快速操作仍困难。后来的OFT能看多台相机，不能算成原版已有的能力。

### 03 π₀

所用版本：2410.24164v4，17页。[原论文PDF](https://arxiv.org/pdf/2410.24164v4) · [原文来源](https://arxiv.org/abs/2410.24164v4)

- **问题：** 怎样让会读图和文字的模型，也能算出细致、连贯的多步动作？
- **输入 → 输出：** 多台相机、指令和机器人状态 → 一次计算一段未来动作 → 执行其中的动作。
- **核心改动：** 接上专门算动作的网络。从随机数字开始，反复往像示范动作的方向修改，这叫flow matching。先练多种任务，再专门练具体任务。
- **证据：** Figure 7（p.8）看不专门训练就测试的成绩；Figure 11（p.10）比较给多少条新示范；Figure 13（p.11）看专门练复杂任务的效果。网络组成见Figure 3（p.4）。
- **边界：** §VII（p.11–12）：有些任务仍做不稳。每种示范该用多少、换任务或换机器人后还行不行，都没有完全回答。要分清测试前是否专门练过。

### 04 Open X-Embodiment / RT-X

所用版本：2310.08864v9，12页。[原论文PDF](https://arxiv.org/pdf/2310.08864v9) · [原文来源](https://arxiv.org/abs/2310.08864v9)

- **问题：** 不同机构和不同机器人的示范，能不能整理到一起，帮助彼此学习？
- **输入 → 输出：** 各机器人的操作记录 → 共同的数据格式；RT-X再根据画面和指令输出动作编号。
- **核心改动：** 整理跨机构、跨机器人的示范，再用RT-1-X和RT-2-X检查：加上别的机器人的数据，目标机器人的成绩是否提高。
- **证据：** Figure 4、5（p.5–6）比较只用本机器人数据，与加入其他机器人数据的成绩。Figure 2（p.3）介绍数据，Figure 3（p.4）介绍模型。
- **边界：** §VI（p.6–7）：测试没覆盖所有类型的机器人。文件格式一样，不代表移动一单位或某个坐标方向的含义也一样。新机器人仍可能需要继续训练。

### 05 Octo

所用版本：2405.12213v2，17页。[原论文PDF](https://arxiv.org/pdf/2405.12213v2) · [原文来源](https://arxiv.org/abs/2405.12213v2)

- **问题：** 换了摄像头、任务要求或机器人，能否用少量新示范继续训练，而不用从头学？
- **输入 → 输出：** 图像、可选的机器人状态，加指令或目标图片 → 计算一段未来动作。
- **核心改动：** 把读入数据和输出动作的部分做成可更换的模块，用约80万条示范先训练。算动作时，从随机数字开始多次修改。
- **证据：** Table I（p.7）比较先练共享数据再练目标任务，与直接从零训练；Table II（p.7）分别改变网络和数据。Figure 5（p.6）是不针对任务再练的成绩，Figure 2（p.3）是网络组成。
- **边界：** §V（p.8）：能更换输入模块，不等于换任何相机或机器人都不用再练。是否会看腕部相机、是否听指令，还受训练数据影响。

### 06 FAST

所用版本：2501.09747v1，19页。[原论文PDF](https://arxiv.org/pdf/2501.09747v1) · [原文来源](https://arxiv.org/abs/2501.09747v1)

- **问题：** 动作记录得很密时，相邻数值往往很相似。怎样让模型少预测一些编号？
- **输入 → 输出：** 一段动作 → 描述整段变化的数字 → 调整精度并取整 → 更短的编号串；执行前还原成动作。
- **核心改动：** DCT把整段动作的变化写成多条快慢不同的起伏曲线相加，记录每条曲线占多少；再取整，用BPE给常见数字组合分配短编号。FAST+是通用的编号工具，π₀-FAST是使用它的机器人模型。
- **证据：** Figure 4（p.5）看动作怎样变成短编号；Figure 6（p.8）比较几种记录办法的学习效果；Figure 11（p.10）和Figure 1检查训练花费的时间。
- **边界：** §VI-E、§VII（p.9–11）：最高约5倍的加快说的是训练时间。使用时编号仍要逐个预测，不一定比π₀更快。记录越短，也可能损失更多动作细节。

<a id="paper-07"></a>

### 07 π₀.₅

所用版本：2504.16054v1，19页。[原论文PDF](https://arxiv.org/pdf/2504.16054v1) · [原文来源](https://arxiv.org/abs/2504.16054v1)

- **问题：** 能否到没有用于训练的家庭里，完成由多个步骤组成的整理任务？
- **输入 → 输出：** 图像、任务要求和机器人状态 → 当前该做哪个小步骤 → 对应的多步动作。
- **核心改动：** 一起练机器人动作、看图文字任务和操作步骤。先用FAST编号学动作，再继续训练直接算动作的部分，也学习选择当前步骤。
- **证据：** Figure 7（p.8）看新家庭里完成了多少步骤；Figure 10、11（p.10）分别去掉一些训练资料，检查成绩怎么变。去掉其他机器人数据会退步，网页数据是否有帮助取决于测试，不是每次差异都明显。训练过程见Figure 3（p.4）。
- **边界：** §VI（p.11–12）：陌生把手、遮挡或选错当前步骤仍会让它失败。房子是新的，不代表所有动作都没练过；也不能说明到任何家庭都可靠。

### 08 SmolVLA

所用版本：2506.01844v1，24页。[原论文PDF](https://arxiv.org/pdf/2506.01844v1) · [原文来源](https://arxiv.org/abs/2506.01844v1)

- **问题：** 能否用较小的模型和社区示范，减少训练与运行花费？
- **输入 → 输出：** 多台相机、指令和机器人状态 → 算出一段动作；可以边执行当前段，边计算下一段。
- **核心改动：** 用约4.5亿参数的模型，减少部分网络层，并用社区示范训练。把计算下一段和执行当前段同时进行，减少等待。
- **证据：** Table 2–4（p.11）比较仿真与实机成绩；Figure 5（p.12）中，边算边做缩短了任务时间，但排序任务成功率下降。Figure 1看网络组成，Table 6–13（p.13–14）分别去掉组件做比较。
- **边界：** §5.1（p.14–15）：原来的社区训练数据主要来自SO100。机器人种类和数据量仍有限，换平台后专门练过的成绩不能说成无需训练就能用。

<a id="paper-09"></a>

### 09 OpenVLA-OFT

所用版本：2502.19645v2，24页。[原论文PDF](https://arxiv.org/pdf/2502.19645v2) · [原文来源](https://arxiv.org/abs/2502.19645v2)

- **问题：** 原版OpenVLA算动作慢，能否在继续训练时把速度和成功率一起改善？
- **输入 → 输出：** LIBERO常用设置：主相机、腕部相机、指令和状态 → 一次直接给出未来8步的动作数值。
- **核心改动：** 把逐个输出编号改成同时预测多步数值。训练时按预测值与示范值相差多少扣分（L1误差）。OFT+还可让指令直接调整图像处理过程。
- **证据：** Figure 2（p.3）列出改了哪些计算步骤；Table I、II（p.6）比较各项改动和速度；Table IV（p.17）列具体设置。在作者对应测试里，LIBERO平均成功率从76.5%到97.1%。
- **边界：** §VIII（p.10）：同一情况有几种合理做法时，直接给一组数值较难保留这些选择。每秒算出的动作多了，不等于整项任务也按同样倍数变快。

<a id="paper-10"></a>

### 10 LIBERO

所用版本：2306.03310v2，44页。[原论文PDF](https://arxiv.org/pdf/2306.03310v2) · [原文来源](https://arxiv.org/abs/2306.03310v2)

- **问题：** 机器人学了新任务以后，还记得旧任务吗？旧知识能不能帮助新任务？
- **输入 → 输出：** 仿真任务、起始场景和示范 → 训练和执行测试 → 完成比例、学新后忘旧的程度等分数。
- **核心改动：** 提供一套可生成和组合的任务，把物体、位置关系和操作做法分别改变，方便检查哪种旧经验有帮助。
- **证据：** §5.2（p.7–10）比较不同网络与训练办法，检查旧任务遗忘和对新任务的帮助。Figure 1、§4.2（p.2、5）看任务怎样分；§5.1和Figure 3（p.6–7）看各项分数怎样算。
- **边界：** §7（p.10）：仿真任务范围有限。原论文测“学新忘旧”的分数，与后续VLA测“整项做成多少次”的成功率不同，也不能直接证明实机可靠。

### 11 LIBERO-Plus

- **问题：** 平时测试分很高的机器人，换角度、改光照或让画面变差后，还能做成吗？
- **输入 → 输出：** LIBERO任务加上不同变化 → 机器人边看边做 → 记录每种条件下的成功次数。

### 12 ACT

所用版本：2304.13705v1，18页。[原论文PDF](https://arxiv.org/pdf/2304.13705v1) · [原文来源](https://arxiv.org/abs/2304.13705v1)

- **问题：** 怎样让低成本机器人从少量示范里学到连贯动作，减少越做越偏？
- **输入 → 输出：** 相机和关节状态 → 预测未来多步 → 把前后几次对同一时刻的预测加权平均后执行。

### 13 Diffusion Policy

所用版本：2303.04137v5，19页。[原论文PDF](https://arxiv.org/pdf/2303.04137v5) · [原文来源](https://arxiv.org/abs/2303.04137v5)

- **问题：** 同一画面下，绕左边或右边都可能合理。模型怎样保留不同的动作选择？
- **输入 → 输出：** 最近的画面和机器人状态 → 从随机数字开始反复修改 → 得到一段动作，先做几步再看画面。
- **核心改动：** 训练模型把被随机数字扰乱的动作改好，这叫扩散方法。执行时只先做预测中的一部分，重新观察后再算。
- **证据：** §4.1（p.4–5）看同一情况的不同做法；§5.4（p.8–9）分别改变算动作和执行的设置。§5.2（p.7）解释评分，Figure 2（p.3）区分预测多少步和先执行多少步。
- **边界：** §9（p.13）：还需要相关示范。反复计算要花时间；先做得越多，重新看画面的机会越晚。能生成多种动作，不等于能听懂任意新要求。

### 14 LoRA

所用版本：2106.09685v2，26页。[原论文PDF](https://arxiv.org/pdf/2106.09685v2) · [原文来源](https://arxiv.org/abs/2106.09685v2)

- **问题：** 继续训练大模型时，能不能少更新、少保存一些参数？
- **输入 → 输出：** 已有模型与新数据 → 学两个较小矩阵 → 用它们对原模型作小幅修改。
- **核心改动：** 保留原来的大矩阵，只训练新增的两个小矩阵，用它们的乘积表示修改量。这叫LoRA；它不规定机器人怎样输出动作。
- **证据：** §5（p.5–8）在语言任务里比较少量参数训练与全部参数训练。§7.1–7.2（p.10）改变更新位置和小矩阵大小；Figure 1与§4（p.1、4–5）看两个小矩阵怎样改模型。
- **边界：** 原论文主要测语言模型，不能直接当作VLA成绩或显存需求。原模型、训练中的中间结果和动作输出部分仍要占显存。

### 16 EGR

- **输入 → 输出：** 每帧、每个传感器与任务有关的估计分数 → 改变训练要求 → 学习怎样使用传感器。
- **核心改动：** 无关传感器的数据变了，动作尽量不变；有用传感器单独留下时，也练习完成任务。使用模型时不用增加这套训练计算。

### 18 PHASER

### 22 CARE

所用来源：arXiv:2609.32550v1 作者摘要，2026-10-22核对。**阅读深度：只核对了摘要，还没有逐项检查全文和代码。** [原文来源](https://arxiv.org/abs/2609.32550v1) · [论文PDF](https://arxiv.org/pdf/2609.32550v1)

- **问题：** 只坏一帧为什么也可能做错很久？先执行多少步会有什么影响？
- **输入 → 输出：** 比较前后两次预测的动作 → 决定先做几步 → 做完后重新观察。
- **核心改动：** 根据前后动作预测是否一致，改变先执行的步数。少执行几步，就能早点重新看画面和算动作。
- **证据：** 摘要提到额外计算较少，正常条件下的成绩得以保持。全文重点看哪一步破坏画面、怎样决定执行步数，以及固定执行步数时的比较。
- **边界：** 这是改变执行方式，不是改变训练数据。比较不同方法的成绩时，也要说明每次先做几步。

## 五、这些说法容易弄混

| 说法 | 具体区别 |
| --- | --- |
| 指令与动作编号 | 指令说想做什么；编号表示怎样移动。 |
| 动作有8项与未来8步 | RT-2的8项描述当前一步；OFT的8步是后面8个时刻。 |
| 一次预测多步与一次算完 | π₀仍要反复修改数字；OFT可以一次直接给出结果。 |
| 预测几步、先做几步、计算时改几次 | 是三个可以分别设置的数字。 |
| 训练更快与机器人做得更快 | FAST最高约5倍的加快，指训练花的时间。 |
| 更新参数少与显存一定小 | 原模型和计算中的中间结果仍要放进显存。 |
| 换了房间与学了新动作 | 到新房间完成熟悉操作，不等于会所有新技能。 |
| 完整做成与部分得分 | 做完几个步骤的分数，不是整项任务的成功率。 |
| 挑输入、挑示范与重练旧示范 | 改的是训练过程的不同地方。 |
| 相机坏了还能做与看得更清楚 | 也可能只是转而使用另一台相机。 |
